## 已确认的产品方向

用户从学习作品主动进入独立页面，围绕自己的真实场景继续对话，而不是在原学习页面里塞一个大型功能面板。

结合三方面：

1. 用户的困境决定要解决什么，以及其目标、限制与当下状态。
2. 原文提供理解与判断的线索，但不预设原文一定正确或一定适用。
3. 知乎公开自述的相似经历提供不同路径、代价与局限，不保证别人走通的路适合用户。

需要时补充学习方法或其他文章：补背景、补做法、补不同看法；优先直接帮助用户处理眼前的一件事，不再制造一份长长的待学清单。

## 待实现的建议顺序

1. **独立页面与连续体验。** 暂名「知行」，入口「用到我的生活里」。继承文章与学习位置，可返回继续阅读。阅读到底或媒体结束时只轻量邀请，不自动跳走，不把滑到底等同学会。
2. **围绕场景的对话。** 一次只追问会改变建议的关键条件；带上原文依据，不要求重填问卷。信息足够时给可尝试的一步或更清楚的判断；允许继续纠正，不强制形成任务清单。
3. **可追溯的经验与补充资料。** 先整理小范围可核对的资料集，逐项记录原链接、作者公开署名、相关段落、相似与不同；再验证实时检索接口、正文访问与引用边界。没有合适来源就明确缺失。
4. **自然接回学习。** 推荐说明针对哪个问题；用户可看原文或一起读相关段落。补充学习后保留原对话与困境，不重新介绍自己。

以上命名、具体布局和资料获取方案为建议，尚未完整设计或实现。不创建固定多轮脚本，不自动修改长期 Skill；私人生活场景不进入长期画像。

## 怎样验收

- 原项目文件、数据库、线上服务和 GitHub 不受副本开发影响。
- 新页面可从真实学习位置进入，并回到相同进度。

- 推荐能说明填补了什么缺口，用户可拒绝或纠正。
- 用户能形成更清楚的判断或可尝试的一步；不把阅读数、点击数当学习效果证据。
